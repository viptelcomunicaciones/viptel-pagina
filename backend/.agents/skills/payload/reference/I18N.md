# Internacionalización (i18n) en Payload CMS

## Configuración global

```typescript
// En payload.config.ts
localization: {
  locales: ['es', 'en'],
  defaultLocale: 'es',
  fallback: true,  // Si falta traducción, usa default locale
}
```

## Locales activos

| Locale | Código | Default |
|---|---|---|
| Español | `es` | Sí |
| Inglés | `en` | No |

## Colecciones localizadas

| Colección | Campos localizados |
|---|---|
| Categories | `title` |
| Pages | `title`, `hero.richText`, `layout` (blocks) |
| Posts | `title`, `content`, `excerpt` |
| Projects | `title`, `description`, `content` |
| Services | `title`, `shortDescription`, `description`, `features`, `pricing`, `faq`, `layout` |

## Globals localizados

| Global | Campos localizados |
|---|---|
| Header | `navItems` |
| Footer | `navItems` |

## Fallback

Con `fallback: true`, si un campo localizado no tiene valor en el locale solicitado, Payload devuelve el valor del locale por defecto (`es`).

Ejemplo: Si un post no tiene contenido en inglés, la API devuelve el contenido en español.

## Cómo se solicita un locale

### REST API
```
GET /api/posts?locale=en
GET /api/pages?locale=es&depth=2
```

### GraphQL
```graphql
query {
  Posts(locale: en) {
    docs { title content }
  }
}
```

## Preview con locale

En `generatePreviewPath` (`src/utilities/generatePreviewPath.ts`):

```typescript
export const generatePreviewPath = ({ slug, locale }) => {
  const prefix = locale === 'es' ? '' : `/${locale}`
  return `${prefix}/${slug}?preview=true`
}
```

- `es` → `/home?preview=true`
- `en` → `/en/home?preview=true`

## URL generator del SEO plugin

```typescript
generateURL: ({ doc, locale }) => {
  const prefix = locale === 'es' ? '' : `/${locale}`
  const base = collectionSlug === 'services'
    ? `/services/${doc.slug}`
    : `/${doc.slug}`
  return `${FRONTEND_URL}${prefix}${base}`
}
```

## Migración — Tablas de locales

Cada colección localizada genera una tabla `{collection}_locales` en PostgreSQL. Ejemplo:
- `pages_locales` — almacena las traducciones de campos localizados de pages
- `services_locales` — lo mismo para services

La tabla principal guarda los campos no localizados; las tablas `_locales` guardan una fila por cada combinación de documento + locale.
